# 2026-10-01（凌晨 · 咨询，尚未动手）

## 咨询一：对接微信小程序自动跟行情
- 用户问：有个每天更新行情的小程序，能不能对接进来自动同步？
- 结论：小程序**没有对外读接口**，四条路 ——
  ① 找它背后的数据源头（最优，很多行情小程序只是壳）
  ② 抓小程序网络请求 / 反编译 `.wxapkg`（能做但脆：签名要复刻、对方一更新就失效、微信有风控、绕技术保护措施有法律边界）
  ③ **截图 + 视觉识别**（推荐：永不失效、零合规风险，用户已有能跑 Qwen3-VL 的账号）
  ④ 手机自动化（要常开安卓机，微信风控，iPhone 基本不可行）
- ❗真正的难点不是拿数据，是**「小程序商品名 ↔ 系统 `product_code`」的映射表**（类似「Whoo水妍/水姸」那种坑），不做这步抓回来全是废数据

## 咨询二：能不能在出入库网站里植入一个 AI
- 结论：可以，门槛不高（HTTPS / Node 后端 / 数据库 / 已付费模型账号都有）
- 三种形态：① 站内问答助手（右下角按钮，问「这个月赚了多少」）；② **AI 干具体的活**（行情截图识别、商品图识别、异常提醒）← 更看好；③ 本地跑模型 ← 轻量服务器跑不动，不现实
- ❗❗**定下架构原则（最重要）**：**AI 只做两件事 —— 听懂意图、复述人话；所有金额一律由现有 SQL 接口计算。**
  大模型算术不可靠且错得很自信，绝不让模型自己算账。第一版只给「读 + 答」，不给写权限。
- 成本：按量计费，这种用量一个月几块到几十块；隐私上数据会发给模型服务商（国内的硅基流动），与竞彩「绝不出本机」性质不同，由用户判断

## 用户选定「自动录行情」，并给了两条硬要求
1. 行情表里**他没录入的商品不用管**，只匹配系统里有的

## 算法上踩的两个坑（都验证过、已修）
1. **奔富407 只有 0.42 分** —— 系统 spec 是「750ml」而行情名不写容量，「spec 没命中就减半」把一字不差的商品打到 0.42
   → 改成「**spec 命中才加分，没写规格只轻微扣 0.95**」
2. **「小米手环10 黑」被配到「银色」那款** —— 2-gram 下同款不同色比同色不同前缀更"像"
   → 加**颜色冲突重罚 ×0.45**，且只扫**尾部 4 字**取颜色字（避开"红米/小米/金士顿"误伤）
- 另修：`相纸 -60张/盒` 被当"多色斜杠"拆坏 → 加单位字表挡掉

## 修 bug：行情图「暂无价格数据」（用户报，10-01）
- 现象：奔富389/407 导入行情后，商品信息表行情图仍显示「暂无价格数据」
- ❗根因：`POST /price-import/commit` 写入时**只写 `product_code`，没写 `product_id`**（null）；而**商品表行情图是按 `product_id` 查的** → 漏掉 null 行 → 图空白
  - 奔富389/407 之前**从没录过行情**，库里只有这两条 null 行 → 整图全空（其它商品有历史行兜着，所以一直没暴露）

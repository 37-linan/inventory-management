## 新增：物品「套装」功能（已上线）

**需求澄清过程（重要）**：用户最初说"加一个字段是否套装，选了是编码就可以扫多次"，
容易误解成"同一编码重复扫"。经确认真实场景是：
- 一个套装 = **多个不同编码**的商品（如 A、B 各有自己的条码），商品表里各自一条记录
- 这些商品填**同一个「套装名」**，名称/规格/单位/行情/类型相同
- 入库时各编码都会被扫到 → 同一张单出现多条记录（用户确认这是正常现象，不要去重）
- **一整套只录一个行情价**（每个组成商品都录同一个价），算利润时按"套"算

**改动**
- DB：`main_products` 加 `is_set BOOLEAN` + `set_name VARCHAR(100)`；
  `ensureSetColumns(db)` 幂等加列，挂在 main-cloud.js 的 `router.use` 上统一 ensure
- 后端 `routes/main-cloud.js`：
  - 新增 `loadSetNameMap` / `groupItemsBySet` / `setUnitsOf` 三个共用函数
  - `/order-profit`、`/dashboard`、`/ledger` 三处都改为：同单内同 set_name 归一组，
    **销售额 = 套价 × 套数，只算一次**；套数 = 组内第一个编码的数量合计；
    组内任一条出库即视为该套已出库；明细/台账里只有"代表行"记销售额，其余标 `set_member`
  - 商品接口 POST/PUT 支持 is_set/set_name（"传了才更新"，旧缓存页面保存不会抹掉标记）
  - `/inventory` 返回 `set_units`（可成套数 = 同套装名各编码库存的最小值）
- 前端：products.js 添加/编辑物品加「是否套装」下拉 + 套装名输入框（`_onSetChange` 控显隐）；
  列表显示「套装 · 套名」徽章；transactions.js 单利润明细、出库台账、出库选商品弹窗加套装标注，
  库存按「套」显示

**验证**
- `.workbuddy/tmp/set-bundle-test.js`：vm 加载真实路由 + mock db，19 项断言全绿
  （套装算一次、只扫一个码也正确、同编码多条也归成 2 套、三处口径一致）
- `.workbuddy/tmp/frontend-set-test.js`：25 项断言全绿（表单开关、必填校验、回显、明细标注）
- 线上：SW v35、md5 一致、新列已建、三个利润接口 200；Git `81afab7` 已推

## 追加：商品信息表把套装多个编码合并成一行（已上线）

**用户反馈（带截图）**：套装的两个编码在商品列表里各占一行、套装徽章还重复显示，
"我要的是填完过后他们两个编码是在一起的，然后用一个名字，然后用同一行就可以了"。

**改动（纯前端，只改 products.js）**
- 新增 `_buildDisplayRows(items)`：同一类型分组内，`set_name` 非空的多个商品合并成一个显示行
  （位置取第一个成员的顺序），普通商品各自一行
- 新增 `_uniqList(arr)`：规格/单位/名称/行情取**并集去重**，不同值用 ` / ` 连起来显示（不丢信息）；
  名称只写一次，套装徽章只出现一次；编码列竖排多个 `<code>`，点哪个就编辑哪个
- 新增 `_todayStr()`（本地时区，避免 toISOString 差 8 小时）、`_setRef(rowId)`、
  `deleteSet()`（一次删掉该套装所有编码）、`setPriceForSet()` / `submitSetPrice()`
  （**一次把整套价写到该套装每个编码上**，接口按 product_id+date upsert，循环提交安全）
- ⚠️ 按钮回调统一走**行索引** `this._rowRefs[rowId]`，不把套装名/编码拼进 onclick（中文+引号高危）
- 拖拽排序：套装行 `data-pids="11,12"`，收集新顺序时先读 `data-pids` 再回退 `data-pid`
- 分组标题统计改为「共 N 项（M 个编码）」

**验证**

  规格并集、行情图容器 5 个都在、删除套装删 2 个 id、整套价写 2 条行情）

## 追加：套装改成「多扫几个码」，不再手填套装名（已上线）

**用户反馈（带截图）**：
1. 截图里编码列第二个位置（红框）是空的 —— 期望套装的两个编码都在那里显示
2. "添加物品我选了如果是套装的话，你弹出来的应该不是套装名，你弹出来的那个格子应该是扫多一个码的"

**先查数据定位（只读）**：`psql` 查 `main_products` 发现线上 `is_set=true` 的**只有 1 条**
（id 150 `8809949537477` Whoo水妍两件套），第二个编码 8809496537514 **已被删掉** →
所以红框是空的、徽章显示「1 个编码」。另外那条的 `set_name='Whoo水姸两件套'` 但
`name='Whoo水妍两件套'`（手打错字：姸/妍）——正是"让用户手填套装名"的典型翻车。

**改动**
- 后端 `routes/main-cloud.js`：
  - `set_name` **一律自动取 `name`**（POST/PUT 都无视前端传来的 set_name）；
    删掉「勾了套装必须填套装名」的 400
  - 新增 `syncSetNameRename(db,id,新名)`：改名称时把**整套一起改名**（UPDATE ... WHERE set_name=旧名），
    否则同一套会被拆成两组；顺带把历史错别字组名修正过来
  - `is_set=false` → set_name 置空 = 退出该套
- 前端 `products.js`：
  - 新增 `_setBlockHtml(prefix, isSet[, 顶部提示])`：是否套装 选"是" → 出现「再扫一个码」
    （`{prefix}-set-code-input` + 📷 + 「＋加入」），下面是已加编码胶囊（可 ×移除）
  - `addSetCode / removeSetCode / _renderSetCodeList / _setCodesOf / _resetSetCodes`
  - `triggerBarcodeScan(inputId, afterToken)` 加第二个参数：`set-product` / `set-edit` / `setadd`
    → **扫完自动加入**，不用再点一次（只有传了 token 才这样，其他扫码入口行为不变）
  - `submitAdd`：主码 + 所有其它码一起建，`set_name = name`
  - `_joinSet(code, setName, fields)`：**已存在的编码只 PUT 并入该套（不动它原有名称/规格）**，
    新编码才 POST 新建（按代表商品的信息）
  - 套装行操作列加「＋ 加码」→ `addCodeToSet` / `submitAddCodeToSet`（把已有/新编码并进该套）
  - 徽章文案改为「套装 · N 个编码」（组名=名称，写出来是重复信息）

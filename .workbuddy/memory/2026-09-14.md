## 扫码排查：出入库台账 vs 产品信息表（结论：同一套代码，勿再换算法）
- 核实: 所有扫码入口都调用 products.js 的 `triggerBarcodeScan(inputId)`
  - 产品信息表 添加物品 📷 → triggerBarcodeScan('product-code')
  - 入库单 扫码 → triggerBarcodeScan('inbound-order' / 'inbound-code')
  - 出库单 扫码 → triggerBarcodeScan('outbound-code' / 'outbound-order-no')
  - 补单号 扫码 → triggerBarcodeScan('fill-order-no')
  - 全部 → BarcodeScanner.startScan()（barcode.js，全站唯一扫码模块）
- 服务端 /home/ubuntu/inventory-app/public/js/modules/barcode.js 与本地 MD5 一致 (4bc5431738aae7fc9394d7c53d3575b5)
- 唯一能造成"同代码不同效果"的是分支：startScan 用 4s 超时竞速 getUserMedia
  - 相机开 → 实时视频(640x480 抽帧 + 逐帧解码) ← 准确率低
  - 相机失败/超时 → _startPhotoScan(系统相机拍照 + 服务端 ZXing) ← 准确率高
- iPhone 限制: Safari BarcodeDetector 对商品条码(EAN-13)支持差，实时路径实际靠 Quagga 硬扛
- 用户决定: 保持现状（点扫码直接进实时画面），暂不改
- 若日后要提准确率（不改界面）：① 检测原生检测器是否真支持 ean_13，不支持则跳过别空转；② 摄像头请求 720p + 按视频真实分辨率抽帧（保真度更高，可能稍慢）

## 用户反馈"变成拍照了"→ 修复相机打开链路（barcode.js startScan）
- 澄清: 代码始终是实时优先；`_startPhotoScan` 只在第104行 catch 里被调用（唯一入口），即"摄像头打不开"才退到拍照
- 三个致因一并修掉:
  1. 打开超时 4s → 12s（iPhone 首次/切应用后开相机常超 4s，过早判失败会误退拍照）
  2. 新增约束回退: 带 `facingMode/640x480` 失败 → 用 `{video:true}` 再试一次（部分 iOS 对约束挑剔）
  3. 修复摄像头泄漏: 超时后若相机才打开，把这条流 stop 掉（原代码 race 失败时 stream 未赋值 → 流没人关 → 后续每次扫码都开不了相机只能拍照）
- 界面零变化; sw.js 缓存 v6 → v7; 部署后 barcode.js MD5: d632b18287cbbb1f412a2937ae394d06

## 用户反馈"没用，还是拍照" → 彻底拆掉静默兜底（v8）
- 先核实: 服务器 barcode.js MD5 = 本地 = d632b182，即 v7 确实上线，是**真失败**而非旧缓存
- 根因判定: `startScan` 里 getUserMedia 一失败就 catch → `_startPhotoScan`，全程无任何提示 → 用户只看到拍照页，看不到原因，无法自救
- 新逻辑（barcode.js）：
  1. `navigator.mediaDevices.getUserMedia` 不存在 → 明确提示。若非安全上下文（用 http://IP:3000 访问）会直接说"请改用 https://nanyishangmao.cn"
  2. 三档约束逐级放宽（1280x720 后置 → 后置 → video:true），`_gumWithTimeout(25s)`；NotAllowedError/SecurityError 直接跳出不再放宽
  3. 失败 → `_showCameraError()`：把真实原因翻译成人话（权限被拒/被占用/超时）+ 三个按钮「🔄重新打开实时摄像头 / 📸改用拍照识别 / ⌨️手动输入」+ 页脚打印 origin 与是否安全连接
  4. **不再自动退拍照**，`_startPhotoScan` 现在只有用户手点才进入
  5. `_startVideoScan` 改 async：显式 `video.play()`（iOS 只给 autoplay 有时不出帧→全黑白跑）+ `_waitVideoReady()` 等 readyState>=2 再解码
  6. Quagga 抽帧改按视频真实分辨率（上限 1280 宽）+ `willReadFrequently`，逐帧间隔 300→200ms
  7. 可选链 `?.` 全部去掉，改 `isSecureCtx()` 全局函数
- 移除残留 OCR：`_startPhotoScan` 第 5 步与 `_doCropAndDecode` 里的 `/api/ocr-text` 调用已删，前端现已零 OCR
- sw.js: v7 → v8，且 **.js/.css 改为网络优先**（缓存优先曾导致手机上一直跑旧代码）；index.html 引用改为 `barcode.js?v=8`
- 部署后 MD5: barcode.js 85c12174d7511490cff8a1d682a3c0d4 / sw.js 9c9eed87b7f4fe7fffe9d9c57bdc5b24；GitHub 推送 38aa241
- 待用户实测: 点扫码应直接是实时画面；若仍失败，错误页会显示具体原因，把那张截图发来即可定位

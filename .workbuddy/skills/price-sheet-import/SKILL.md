# 行情表截图 → 可导入文字

## 用户要什么（原话）
> 我以后会发截图给你，然后你先进行初步的筛选，就是筛选我系统里面有的商品，然后把它的商品名加行情给我文字，然后让我可以导入行情那里导入

## 铁律
1. **只保留系统里有的商品** —— 行情表里没录进系统的，一个字都不要出现在结果里。
2. **同款多编码必须问用户** —— 用户原话「就算你知道这个商品是那个，但你也先问我」。哪怕 100% 确定也要把歧义抛给他拍板（`AskUserQuestion`，最多一次问 4 个）。
3. **输出用「系统商品名」**，不是行情表原名 —— 这样导入时匹配直接 `auto` 命中，用户不用在候选里挑。
4. **绝不替用户写库** —— 只给文字，导入动作由用户在界面上做。

## 步骤

### 1. 读图，把行转录成「名称 价格」
- 行情表常分**左右两块，两块都要读**（常见：左边相机、右边配件/酒水）。
- 分组标题（如「富士拍立得mini13国行」）要跟下面的颜色行**拼起来**再匹配 → `富士拍立得mini13国行 香芋紫 605`。
- 表头/说明行不要（「没价格不代表不收」「所有品类都可以在报单群问画风」、地址行）。

### 2. 拉系统商品清单
```bash
cd F:/出入库管理系统 && curl -s -m 30 --compressed "https://nanyishangmao.cn/api/main/products" -o .workbuddy/tmp/prod-<日期>.json
```
⚠️ 沙箱会**锁覆盖已存在文件**（EPERM）→ 用**当天新文件名**，别复用。
⚠️ `curl` 偶发下载被截断 → 改 `node -e` + `fetch` 更稳。

### 3. 跑系统自己的配对接口（当参考，不当结论）
`POST https://nanyishangmao.cn/api/main/price-import/match`，body `{rows:[{name,price}]}`。
每条返回 `{code, match_name, match_spec, score, source, candidates[]}`，`source` ∈ `alias|auto|likely|ambiguous|low|none`。

❗**自动匹配有噪声**，实测把「minise白色」配到「GPW3代白色」52%、「minise配件盒」配到「拍立得mini13配件盒」47%。
**分值高 ≠ 对**，只当候选参考，**结论必须人工过**。

### 4. 人工初筛
逐行判断系统里**有没有**这个商品：
- 没有 → 丢弃
- 有且唯一 → 收
- 有但**同款多个编码**（国行/海外、国行/国际版、单白/日版…）→ **问用户**

### 5. 输出
用**代码块**给一段纯文本，一行一个「系统商品名 价格」，**不加任何注释/分组标题**。例：
```
奔富389 330
拍立得相机mini13 香芋紫 605
拍立得双白盒装国行 117
```
并**明确告诉用户生效日填哪一天**（= 行情表表头写的日期，"9.29" → `2026-09-29`）。

### 6. 交付前自检（必须 0 失败才发）
真加载 `public/js/modules/products.js` 跑 `_parsePriceText`（行数/名称/价格），再调线上配对接口确认每条首选编码。
脚本样例：`.workbuddy/tmp/verify-import-text-1001.js`。

## 踩过的坑
- 价格在**行尾**；`_parsePriceText` 会自动跳过含「结算价/行情/不代表/全系/品类」的行。
- 名字里的斜杠只在**后段是颜色型号**时才拆多行（`黑/银`）；`相纸 -60张/盒` 的斜杠是量词，不会拆。
- 系统里一个套装 = **多个编码共用一个名称**，行情表可能只给一个名 → 要问是不是整套。
- 「拍立得相机mini13」在系统里是**两个独立编码**（香芋紫 / 蜜瓜绿），不是套装。

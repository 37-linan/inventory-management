# 行情表截图 → 可导入文字

## 用户要什么（原话）
> 我以后会发截图给你，然后你先进行初步的筛选，就是筛选我系统里面有的商品，然后把它的商品名加行情给我文字，然后让我可以导入行情那里导入

## 铁律
1. **只保留系统里有的商品** —— 行情表里没录进系统的，一个字都不要出现在结果里。
2. **同款多编码必须问用户** —— 用户原话「就算你知道这个商品是那个，但你也先问我」。哪怕 100% 确定也要把歧义抛给他拍板（`AskUserQuestion`，最多一次问 4 个）。
3. **输出用「系统商品名」**，不是行情表原名 —— 这样导入时匹配直接 `auto` 命中，用户不用在候选里挑。
4. **绝不替用户写库** —— 只给文字，导入动作由用户在界面上做。

## 步骤

### 1. 读图，把行转录成「名称 价格」
- 行情表常分**左右两块，两块都要读**（常见：左边相机、右边配件/酒水）。
- 分组标题（如「富士拍立得mini13国行」）要跟下面的颜色行**拼起来**再匹配 → `富士拍立得mini13国行 香芋紫 605`。
- 表头/说明行不要（「没价格不代表不收」「所有品类都可以在报单群问画风」、地址行）。

❗❗**必须放大切块读，别直接读整图**。手机截图列窄字密，整图直接看**会读错价格**——实测把「小米小爱音箱Play(增强版) **95**」读成 230，差点录错。
```bash
"C:/Users/nan/.workbuddy/binaries/python/envs/default/Scripts/python.exe" -c "
from PIL import Image; import os
src=r'<截图目录>'; out=r'F:\出入库管理系统\.workbuddy\tmp\crop'
os.makedirs(out,exist_ok=True)
def cut(tag,fn,cols,rows,scale):
    im=Image.open(os.path.join(src,fn)).convert('RGB'); W,H=im.size
    xb=[round(W*i/cols) for i in range(cols+1)]; yb=[round(H*i/rows) for i in range(rows+1)]
    for r in range(rows):
        for c in range(cols):
            t=im.crop((xb[c],yb[r],xb[c+1],yb[r+1]))
            t.resize((int(t.width*scale),int(t.height*scale)),Image.LANCZOS).save(os.path.join(out,f'{tag}_r{r+1}c{c+1}.png'))
cut('sm','数码行情.png',3,3,1.6)   # 列多切 3 列；图小就把放大倍数调大
"
```
- 缩放参考：原图宽 ~1100 → 放大 **2.2~2.5x**；宽 ~2300 的高清图 → **1.6x** 就够。
- ⚠️ **列边界会把整列切掉**（实测资生堂系列正好卡在两块中间）→ 哪块首列文字被截断，就**单独裁一条 3x** 复核。
- 一块一块 Read，边读边记；读完再比对系统清单，别跳步。

### 2. 拉系统商品清单
```bash
cd F:/出入库管理系统 && curl -s -m 30 --compressed "https://nanyishangmao.cn/api/main/products" -o .workbuddy/tmp/prod-<日期>.json
```
⚠️ 沙箱会**锁覆盖已存在文件**（EPERM）→ 用**当天新文件名**，别复用。
⚠️ `curl` 偶发下载被截断 → 改 `node -e` + `fetch` 更稳。

### 3. 跑系统自己的配对接口（当参考，不当结论）
`POST https://nanyishangmao.cn/api/main/price-import/match`，body `{rows:[{name,price}]}`。
每条返回 `{code, match_name, match_spec, score, source, candidates[]}`，`source` ∈ `alias|auto|likely|ambiguous|low|none`。

❗**自动匹配有噪声**，实测把「minise白色」配到「GPW3代白色」52%、「minise配件盒」配到「拍立得mini13配件盒」47%。
**分值高 ≠ 对**，只当候选参考，**结论必须人工过**。

### 4. 人工初筛
逐行判断系统里**有没有**这个商品：
- 没有 → 丢弃
- 有且唯一 → 收
- 有但**同款多个编码**（国行/海外、国行/国际版、单白/日版…）→ **问用户**

### 5. 输出
用**代码块**给一段纯文本，一行一个「系统商品名 价格」，**不加任何注释/分组标题**。例：
```
奔富389 330
拍立得相机mini13 香芋紫 605
拍立得双白盒装国行 117
```
并**明确告诉用户生效日填哪一天**（= 行情表表头写的日期，"9.29" → `2026-09-29`）。

### 6. 交付前自检（必须 0 失败才发）
真加载 `public/js/modules/products.js` 跑 `_parsePriceText`（行数/名称/价格），再调线上配对接口确认每条首选编码。
脚本样例：`.workbuddy/tmp/verify-import-text-1001.js`。

## 踩过的坑
- 价格在**行尾**；`_parsePriceText` 会自动跳过含「结算价/行情/不代表/全系/品类」的行。
- 名字里的斜杠只在**后段是颜色型号**时才拆多行（`黑/银`）；`相纸 -60张/盒` 的斜杠是量词，不会拆。
- 系统里一个套装 = **多个编码共用一个名称**，行情表可能只给一个名 → 要问是不是整套。
- 「拍立得相机mini13」在系统里是**两个独立编码**（香芋紫 / 蜜瓜绿），不是套装。
- 用户导入后若反馈**行情图显示「暂无价格数据」**：是写入时漏 `product_id` 的老 bug（10-01 已修 + 已回填历史行）。让用户**刷新页面**再看即可；若仍空白，查该商品是否有「7 天内」的行情（`PriceChart._seriesFromHistory` 只取最近 7 天，更早的日期图上必然看不到）。

## 美妆 / 日化表的坑（和数码表不一样）
- 同一行常给**两个价**（老款/新款、中文/英文、滋润/清爽、国柜/免税），而系统只有**一个编码** → **必须问用户取哪个**，别自己选。
- 行情表惯用**俗称**，系统存的是**官方全名**：能对上就问用户（「科颜氏白泥」↔「科颜氏二代白泥面膜」、「兰蔻极光洁面」↔「兰蔻净澈焕肤洁面乳」、「IPSA鎏金水」↔「IPSA流金水」）。
- **同名不同品类绝不硬配**：表「欧舒丹樱花**身体乳**250ml」≠ 系统「欧舒丹樱花**沐浴露**二代 200ml」；表「百优全新精纯乳霜」对系统「资生堂百优精纯乳霜」则要问价（202/170）。
- 美妆表**分组标题就是品牌**（「sk-系列」「海蓝之谜系列」「娇韵诗系列」）→ 匹配时品牌名要带上。
